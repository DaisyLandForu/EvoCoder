# Bear Code 评测说明

**当前仓库可复现的评测入口是 `benchmarks/`。** 对外只能引用一次 `python -m benchmarks.runner` 跑出来的 `runs/<run_id>/summary.json`。

历史文档里的 GAIA 165 / HLE 500 Pass@1（含 53.3% / 20.2%，以及关闭折叠后 44.7%）只存在于旧 wiki，仓库没有对应 runner、冻结配置、逐题结果或 Trace。这些数字标为 **历史未验证**，不能由当前代码复现，也不能写进简历。当前 Runtime 没有多模态视觉工具，MM 题型同样属于历史口径。

---

## 1. 当前可复现评测

### 1.1 入口与产物

```bash
python -m benchmarks.runner
```

默认使用 `benchmarks/configs/ci.json` 与 `benchmarks/manifests/ci.manifest.json`。CI 走脚本化 OpenAI 后端，不依赖真实 API Key。失败样本保留在 `results.jsonl`，不会从结果集剔除。

产物目录：

```text
runs/<run_id>/
├── config.json
├── manifest.json
├── results.jsonl
├── traces/<task_id>.jsonl
├── artifacts/
└── summary.json
```

当前最小任务集是 `software-engineering-mini-v1`：

| task_id | 作用 |
|---------|------|
| `se-write-hello` | 写文件 |
| `se-edit-app` | 精确编辑 |
| `se-read-app` | 读文件并回答 |
| `se-wrong-output` | 故意失败样本，验证失败题不会被丢掉 |

### 1.2 冻结配置

一次 run 会把下列项写入 `config.json` / `manifest.json`，之后必须按同一套配置重跑：

- `dataset_version`、`task_ids`
- `task_digest`：对完整任务对象（含 `files`）做哈希，改附件也会变 digest
- `model`、`provider`、`temperature`、`seed`
- `tools`、`skill_version`、`memory_enabled`、`folding_enabled`
- `max_cost_usd`、`max_turns`、超时
- Git SHA

`memory_enabled=false` 时，System Prompt **不注入**本机 Memory Index，避免本机记忆泄漏进对照实验。`tools` 会真正接到 `RuntimeConfig.allowed_tools`。

已有 `run_id` 时，runner 会重建整棵 `runs/<run_id>/`，而不是在旧结果上追加。

### 1.3 指标

`summary.json` 报告：

| 指标 | 含义 |
|------|------|
| Task Success Rate | 本 run 成功题数 / 总题数 |
| 平均 Tool Steps | 平均工具调用次数 |
| P95 Latency | 延迟分位 |
| 平均 Token / 成本 | provider 未回报 usage 时成本为 `null`，不得记成 0 |
| Hard Failure | 权限拒绝、路径逃逸、超时、解析失败等硬失败 |
| NTR | 负迁移率：Champion 通过而 Candidate 失败的比例 |
| 三臂成对差值 | 同一次运行重新生成 `no_skill` / `current_champion` / `candidate` |

每题都有 `results.jsonl` 行和对应 Trace。Skill 治理评测走 `/skill-eval` 或 `agents/skill_shadow_eval.py`，产物在 `.bear/skill-evolution/evaluations/`。

### 1.4 Trace 与成本口径

开启 `--trace` 后，每次根 `chat()` 生成新的 `run_id`。子 Agent 挂到 `subagent_started.step_id`。Skill 后台任务和 Memory 预取必须在 `run_finished` 前 drain / cancel。

REPL 的 `/skill-eval`、`/compact`、`/extract_now` 走独立 Trace run（`_traced_operation`），不会追加到已经结束的对话 run。

`BudgetTracker`：

- 未知 usage 不记成 0，`estimated_cost` 为 `null`
- 设置了 `max_cost` 且存在未知 usage 时，保守停止
- Side Query 调用前也检查预算
- `run_finished` 写本 run 增量；`session_*` 字段写会话累计

脱敏覆盖 `x-api-key`、`proxy-authorization` 及 `-` / `_` / 大小写变体。Prompt 默认只记 hash。

### 1.5 CI

`.github/workflows/ci.yml` 跑：

```text
ruff check agents tests benchmarks
pytest -q
```

不注入真实 API Key。本地测试应在 `evocoder-sandbox:latest` 中执行。

## 2. 历史未验证：GAIA / HLE

下面内容保留给对照旧文档，**不是当前项目结果**。仓库没有 GAIA/HLE runner，无法复现。

### 2.1 旧口径规模

| 数据集 | 原始 benchmark 规模 | 旧文档评测规模 | 旧文档题型分布 |
| --- | ---: | ---: | --- |
| GAIA | 466 题，其中 300 题为留出的测试集 | 165 题 | Text 103、MM 24、File 38 |
| HLE | 2,500 题高难度跨学科题目 | 500 题 | Text 387、MM 113 |
| 合计 | - | 665 题 | 覆盖文本、多模态与文件任务 |

GAIA 面向通用 Assistant，题目通常要求多步信息收集、网页浏览、文件处理、代码执行。HLE 是高难度跨学科推理集。它们曾经被用来讨论会话记忆折叠，但当前 Runtime 既没有对应数据集接入，也没有视觉工具。

### 2.2 旧口径单题流程

旧文档把每题描述为一条 Agent 轨迹：加载任务 → 推理 / 工具调用 → 必要时折叠 → 输出最终答案 → 计算 Pass@1。折叠状态以 `episode_memory`、`working_memory`、`tool_memory` 保存到 `.bear/sessions/`。这套流程今天只作为 Runtime 能力说明，不是可复现评测协议。

### 2.3 Pass@1 定义（历史口径）

`Pass@1` 表示每道题只执行一次，最终是否完成任务：

\[
\mathrm{Pass@1} = \frac{1}{N}\sum_{i=1}^{N}c_i
\]

其中 \(c_i=1\) 表示最终答案正确。这是旧测评的主指标，**不是**当前 `benchmarks/` 的唯一指标。当前 runner 同时报告成功率、工具步数、延迟、成本、硬失败和 Skill Gate。

### 2.4 历史数字（不可复现）

| 数据集 | 类型 | 通过题数 / 总题数 | Pass@1 | 状态 |

| GAIA | MM | 8 / 24 | 33.3 | 历史未验证；当前 Runtime 无多模态工具 |
| GAIA | File | 20 / 38 | 52.6 | 历史未验证 |

| HLE | All | 101 / 500 | 20.2 | 历史未验证 |

| 配置 | GAIA All Pass@1 | 状态 |

## 3. 结论

- 长程状态、Skill 治理和 Trace 由 P0–P2 的测试与 `benchmarks/` 产物支撑。
- 当前可引用的指标只来自 `runs/<run_id>/summary.json`。
- GAIA / HLE 历史分数不能作为当前项目结果对外宣传。
- 当前 Runtime 不宣传多模态能力。
